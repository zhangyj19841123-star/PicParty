# V2 候选版：项目、素材与归档说明

版本：2.0.0-rc.1。记录日期：2026-10-26。本文说明当前源码的实际行为；最终运行结果以同一构建产物的验收报告为准，不把自动测试写成另一台 Mac 已经实测。

## 打开即可拼图

启动后直接进入「临时拼图」，可以立即导入、编辑和导出，无须创建或命名正式项目。编辑后的临时拼图会独立自动保存；上次草稿通过简洁恢复入口和「我的项目 → 临时草稿」打开，不强制弹窗，也不会因开始新拼图自动删除旧草稿。

顶部「存为项目」将当前临时拼图复制为有独立身份的正式项目，之后的编辑自动保存在该项目中。正式项目名称不必唯一，存储 ID 才是身份，重名不会覆盖。项目复制只建立独立文档身份和编辑数据，继续共享外部原图引用；复制已导入项目时也引用原导入项目的素材目录。需要素材独立副本时应重新打包并导入完整 ZIP。「我的项目」提供项目、临时草稿和已删除列表，可搜索、按最近编辑浏览、打开、重命名、复制、移入已删除或恢复。删除需要确认，只改项目的删除状态，不删除原始照片。

「新建拼图」直接开始新的临时工作区；项目操作菜单可新建正式项目、打开旧 `.collage`、另存项目文件副本、打包完整归档和导入归档。高级画布创建仍使用已有尺寸选项，不成为普通拼图的前置步骤。

## 数据保存位置

桌面应用沿用 Tauri 的用户应用数据目录，避免将用户作品写到开发工程或会被替换的 APP Bundle。一般 macOS 路径为：

| 内容 | 默认位置与格式 |
| --- | --- |
| 正式项目 | `~/Library/Application Support/com.framestudio.collage/library-v2/projects/<存储 UUID>/project.json` |
| 临时草稿 | 同一 `library-v2/drafts/<存储 UUID>/project.json` |
| 项目恢复版本 | 对应项目目录的 `recovery/`，保留最多 3 份已校验的前一成功版本 |
| 损坏当前文件的保留副本 | 对应 `recovery/damaged-<时间>-<UUID>.json`；不会拿损坏字节替代有效恢复版 |
| 软删除状态 | 对应项目目录的 `deleted.json`，防止旧恢复版将已删除项目重新带回列表 |
| 已授权素材目录 | 应用数据目录的 `asset-roots-v2/<项目 ID 摘要>.json` |
| 原图代理缓存 | `~/Library/Caches/com.framestudio.collage/proxies/`，可清理的预览缓存，不是原图备份 |
| 工具面板、模板与常用颜色偏好 | 现有 WebView 本地存储，按应用保存，不混入项目画面或撤销历史 |
| 启动诊断 | 应用数据目录的 `logs/startup.jsonl`；只含受控版本、系统、阶段及错误类别 |
| ZIP 归档 | 每次由用户选择位置，不自动上传，也不会覆盖已有同名归档 |

项目库选择 Application Support，而非强制创建 `~/Documents/拼图软件/项目`，符合本工程既有的本地数据架构。项目列表底部显示实际项目库位置。正常项目只保存原图引用、编辑数据和视图状态，不自动复制每张高清原图；从 ZIP 导入的项目则在自己的项目目录保存解出的独立素材。

## 自动保存与恢复

画面数据继续使用 `Project.schemaVersion = 1`：统一画布尺寸、所有页面及框几何、完整图层顺序、背景、图片引用、位置、等比缩放、旋转、裁切焦点、翻转、十项调色、内嵌模板和待排素材均在项目中。项目库外层单独采用 `formatVersion = 2`，包含存储身份、类型、修订编号、更新时间、删除状态和完整 Project，避免改写旧用户文件。

视图状态使用白名单保存：当前页面、同屏/总览模式、可见页和导出勾选、视图缩放、有效的照片/照片框/背景选择。打开时只恢复仍有效的页面和框 ID，不直接接纳任意运行状态。进行中的鼠标事务、未确认的自由变换会话和内存撤销栈不序列化；已应用的画面参数仍会进入保存快照，恢复后可继续编辑。

编辑约 1 秒后防抖自动保存，不要求反复点击保存。写入采用后台串行队列，队列项固定所属项目/草稿身份和不可变快照；原生修订校验拒绝过期写入。切换作品、关键操作和退出会等待保存到最新稳定状态；保存失败会显示重试状态，失败内容保留在当前窗口，不误记为成功。

原生保存先在相同目录写临时文件并同步，再原子提交，最后尝试同步父目录（尽力执行，不承诺断电零丢失）。当前文件损坏时尝试保留的有效恢复版本，并在界面说明已恢复；再次保存前保留损坏字节。遇到未来 `formatVersion` 时拒绝打开和覆盖，不偷偷回退旧快照。单份项目库文件上限为 34 MiB，附加视图状态上限 128 KiB；超限明确失败，上一成功版本不变。

旧的 `frame-studio-recovery-v1` 恢复记录先保留原键和独立备份，再迁移到草稿；迁移摘要防止每次启动重复产生草稿。打开旧 `.collage` 时，为编辑建立独立草稿身份，不自动写回原文件。明确「另存项目文件副本」才输出新的 `.collage`。普通 `.collage` 不是携带原图的备份；需要搬电脑时使用 ZIP 归档。

## 素材断开与智能重连

照片记录在既有 ID、原图路径、文件名、EXIF 有效宽高、内容 BLAKE3 指纹上，增加可选的文件大小、初始路径、来源根目录、相对路径和最多 16 个历史根目录。图层通过素材 ID 引用照片，多个图层使用同一素材时共用来源记录，各自构图和调色仍独立保存。

原生快速登记不会在打开布局前逐张读取完整高清原图。随后在后台检查原路径及素材状态，失联时保留所有框、层序、裁切与调色，尽可能显示已有缓存；缺失素材通过「N 张图片未连接」集中提示。缓存清除或从未生成时只能显示占位，不能凭空恢复高清像素。导出仍要求可读取和验证的真实原图，不会把低清缓存当成高清成品。

重连优先检查原路径，再在已关联根目录、历史根目录和用户指定目录中查找安全的相对路径，必要时在限定目录内搜索同名文件。自动关联必须同时满足内容指纹和有效尺寸；若存在大小记录，也需文件大小一致。唯一可信候选可自动连接，多个相同内容候选要求用户确认；只有同名、尺寸相似或内容不同均不静默替换。重新编码过的图片即使肉眼相似也可能有不同指纹，需要明确定位确认。

「定位素材文件夹」持久记住用户选择的具体目录，并尝试一次恢复项目中其他缺失素材；「定位图片」允许逐张明确选择。后台检查在受限工作线程执行，不阻塞画布，也不递归扫描整台电脑：最多 64 个根目录、6 层子目录、一次 10,000 个目录条目或约 3 秒目录枚举预算（不包含候选图片的指纹和尺寸校验时间），不跟随符号链接目录。达到上限会提示选择更接近原图的子目录，不把未扫描完误报成全部查找完成。

原路径状态每约 2.5 秒检查，并响应窗口重新激活；挂载目录变化使旧扫描缓存失效。同名外接盘在原路径重新挂载时可自动重读，无须重新打开作品。磁盘卷名或目录结构改变后，可能需要选择一次新的素材文件夹；本版本不假定未授权磁盘的任意同名文件就是原图。对未移动且仍在原路径的 Photoshop 保存，继续复用现有外部更新同步功能。

当前 APP 不使用 macOS App Sandbox，目录选择与路径引用依循正常系统文件权限；不会关闭 TCC、请求整盘扫描或用删除隔离属性绕过系统保护。授权目录记录不是绕过系统访问限制的凭据；系统拒绝访问时应重新选择目录或由用户处理相应系统授权。重连保持图层参数与现有撤销中的原图引用，路径/内容的外部刷新本身不新增构图撤销步骤。

## 完整 ZIP 归档

正式项目菜单的「打包归档」创建可继续编辑的完整项目 ZIP。归档只读复制项目登记的全部原图，含背景、待排和已导入素材，原项目引用及原图字节保持不变。包内大致结构为：

```text
<项目名称>/
├── project.json
├── manifest.json
└── assets/
    ├── 000001.png
    ├── 000002.jpg
    └── ...
```

素材用包内唯一顺序名及素材 ID 映射，不会因源文件同名覆盖。`project.json` 的原图路径改为包内相对路径，原机器的初始/历史绝对根目录从归档副本清除。`manifest.json` 使用归档格式版本 2，记录项目/引擎版本、完整标志、项目 BLAKE3、素材 ID、相对路径、字节数、指纹和尺寸；PNG 预览是可选结构，不是原图完整性的替代品。

原图失联、内容变化、尺寸不符或读取失败时拒绝生成标记完整的备份，界面保留重新扫描/定位入口。本候选版不输出部分归档，不会将缺图包误标完整。临时目录完成复制、指纹、ZIP CRC 和结构校验后才提交最终文件；取消或失败不覆盖已有文件。同名归档需要另选名称。

当前 ZIP 安全范围为 Store 输出、Store/Deflate 输入；不支持加密、多卷及 ZIP64。单文件最多 1 GiB，总展开内容最多 2 GiB，条目最多 20,010；超限明确提示。照片本身已压缩，使用标准 Store ZIP 不损失画质。新版本如要放宽上限，应先扩展有界流式读写和相应安全测试，不能仅移除限制。

## 导入与迁移到另一台 Mac

在另一台装有兼容 Frame Studio 的 Mac 上，选择「项目操作 → 导入归档」，选 ZIP 后等待结构和完整性校验。应用使用新的本机存储 UUID 和新的文档身份，解出的素材位于导入项目自己的目录；之后不依赖原机器的绝对路径，也不覆盖本机同名项目。

导入拒绝路径穿越、绝对/非规范路径、非法符号链接或设备文件、重复名、越界偏移、重叠区域、截断、异常展开量、不支持版本、不完整标志、CRC 或 BLAKE3 不符。只允许受限项目结构，素材清单必须与项目和包内素材一一对应。安全临时目录内完成所有校验后才安装为独立项目；后台显示阶段进度并提供取消。

代码及自动测试覆盖“原图路径完全断开后，向独立项目库导入、恢复编辑参数、原生渲染像素一致、再次保存打开和重复导入不覆盖”。这不是另一台物理 Mac 的实测；真实跨 Mac 验收仍需在明确芯片、macOS、APP/ZIP 摘要的另一台机器执行并单独记录。

## 回退及保留边界

升级前 APP、DMG 与摘要保存在 `release/history/pre-v2-20261025/`，Git 基线为 `baseline/pre-v2-upgrade`。回退源码建议使用独立 Git 工作区或先保存当前修改；不要把恢复命令当成删除用户数据的手段。

V2 的项目库与归档是独立的新版容器，不交给旧版覆盖；旧版只能使用升级前已保留的旧项目文件。V2 输出的 `.collage` 可能包含新增素材元数据，严格读取旧格式的 0.1.0 不保证可以打开；应保留原旧文件，并使用 V2 或更高兼容版本继续编辑新作品，不手工删字段猜测兼容。

临时草稿及正式项目不会未经确认自动删除。项目恢复链、缓存预算与临时归档文件有各自明确的维护规则，不等于长期备份：长期留存应定期生成完整 ZIP 并保留在独立位置。候选版没有云同步、远程推送或自动上传。
