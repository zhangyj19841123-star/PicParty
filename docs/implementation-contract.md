# Frame Studio implementation contract

The product is a local macOS ARM64 Tauri 2 / React / Konva application. One project has one document size shared by all pages. Workspace 1/2/3/4/6/8/10 means **independent editable pages visible together**, never photos-per-page. Overview is an interactive thumbnail surface. Photo slots belong to per-page layout templates, but photo transfers do not require matching slot IDs, template IDs or photo counts. Dragging an unselected or already selected photo onto another frame swaps occupied placements or moves into an empty frame, including between two-photo, three-photo and free templates. A selected photo still pans its crop when dragged without a different frame target. Before a transfer, the gesture restores its source's complete pre-drag transform so temporary pan previews cannot alter the carried focus, zoom, rotation or adjustments. Both pages retain their frame geometry and one undo transaction covers the transfer. Overview and the bottom page strip also allow direct dragging from a thumbnail's occupied frame to another specific frame. Canvas and thumbnail transfers are disabled during an active photo free-transform session.

The toolbar exposes a fixed **新增页面** action, Command Shift N, and the native menu action; the page-strip header and overview provide fixed add controls too. These remain reachable without scrolling to the final page. addPage resolves the template from Project.templates before the builtin or application library, so embedded private free templates and saved named templates work after reopening without an external library entry. A new page has its own page/frame IDs and empty placements, uses the chosen template geometry, and is one reversible document edit. New projects and newly created pages initialize all six spacing values—top/right/bottom/left margins, columnGap and rowGap—to zero. Loading older saved projects and duplicating an existing page preserve their saved spacing values.

WorkspacePageCount is the allowlist 1,2,3,4,6,8,10; WorkspaceMode adds overview and previousMode stores a numeric capacity. Toolbar keeps the original 1–4 segments plus a compact **更多** selector for 6/8/10. Native view menu accelerators are Command 6, Command 8 and Command 0 for the new capacities; browser shortcuts match. Command parsing matches the complete `view-N`/`workspace-N` suffix and validates against the allowlist, so view-10 can never be treated as zero. Overview supports one to ten selected independent pages; 5/7/9 selections use capacities 6/8/10 while retaining only the exact selected IDs. workspaceSelectionOnly is ephemeral state that keeps that viewport subset stable during composition edits, cross-page swaps, undo/redo and overview return, without filling unused slots from unrelated pages. An explicit capacity switch can fill from existing pages; no view mode creates project pages or edits export dimensions.

selectedPageIds is the single canonical checked-page set for export and overview batch selection, distinct from activePageId and visiblePageIds. Workspace page headers provide a real accessible **导出** checkbox through PageExportSelection only when more than one page is actually visible; a single visible page hides that control without changing checks. Overview offers per-page checks only for projects with multiple pages. For multi-page projects, the export dialog lists every project page with the same checks and explicit **全选** / **清空** actions. togglePageSelection(id, selected?) and setSelectedPageIds(ids) normalize to existing page IDs in document order and update only that ephemeral selection. Checkbox interactions stop page activation and cannot change visible pages, active page, frame/photo editing, gesture transaction, document revisions or history. Ordinary page browsing activates via setActivePage without replacing export checks; Command/Shift overview selection retains anchored multi-selection. A new project initially checks its first page. Adding a page activates it for editing while preserving the existing checked set and leaving the new page unchecked. Cancelling the final checkbox is valid: no document edit, deletion, undo/redo or navigation may implicitly recheck the active page. Deleted page IDs are filtered out, and undo preserves the currently surviving checks rather than silently adding checked pages. A chosen onlySelected viewport continues reconciling its saved visiblePageIds even if export checks change; only an explicit selection-to-workspace action rebuilds the visible set from the checks.

A project containing exactly one page has no export scope, checkbox list, all/clear controls or empty-selection warning: export targets its only page regardless of the ephemeral checked set. This rule follows the actual project page count, not workspace capacity or the number currently visible. Multi-page project export scopes remain **全部页面**, **所选页面**, and **当前页面**, with document-order IDs and accurate counts, including while the workspace displays only one of those pages. Empty selected scope shows an explanation and disables the export action without substituting the active page. Changing a checkbox in the export dialog or using its all/clear controls switches scope to selected. At the start of run, the current project ID and requested page IDs are frozen before asynchronous directory selection or original synchronization. While busy, the fieldset and checkboxes are disabled. After synchronization, export uses the latest original metadata for the same frozen pages; project changes or deleted requested pages reject the attempt instead of exporting another page. Existing JPG quality-100 defaults and optional PNG output are unchanged.

Screen geometry uses workspaceLayout: preferred grids are 6=3×2, 8=4×2, 10=5×2; narrow viewports reduce columns so all actual pages fit while retaining document aspect ratio. Every page has a disjoint cell hit rectangle and a label bounded to that cell. Frame/background hit tests and document-to-screen inverse mapping use these same views for all rows. Selected odd page subsets return only their actual page count, with no synthetic empty pages. Single-page pan and explicit view zoom retain previous behavior; multi-page views fit their cells. Dense 6/8/10 modes request 512 px proxies for ordinary foreground photos and 1024 px for selected/edited photos, while non-dense single-page preview can use 2048 px. Proxy resolution never changes original-image export.

Photo import and replacement use the entire visible clipped rectangle of the actual target frame, never a nearest-frame guess or invisible photo extent outside its frame. Hovering shows that frame's target outline, and pointer release rechecks the current target. Overlap resolves to the topmost frame; gaps, page gutters, floating panels and dialogs are not photo-frame targets. Finder drops outside a valid target report that a frame is required rather than filling an unrelated frame. Drop coordinates are CSS/window points at the hit-test boundary. In the current Wry macOS backend, AppKit NSPoint values arrive as PhysicalPosition but already use window points; nativeDropPoint must not divide these values by Retina DPR again. Other backends use their physical-pixel-to-CSS conversion. Invalid coordinates or pixel ratios are rejected.

Interactive thumbnails overlay each slot's clipped whole-page normalized bounds, in page.frames layer order, so the pointer identifies a precise frame rather than the page card. Dragging a registered library asset there fills or replaces that frame with a neutral transform; dragging an already placed thumbnail photo swaps occupied placements or moves into an empty frame and retains its complete transform. Native asset and placed-photo drags use pointer capture and a threshold before creating a drag session; release commits, and Escape, pointer cancellation, lost capture, window blur, modal appearance or project changes cancel it. Drag suppression prevents release from also selecting a different page. During pointer drags, overview-scroll scrolls vertically and strip-scroll horizontally when the pointer enters their inside edge bands; scrolling recomputes the hovered target and does not mutate the project. Page order dragging belongs to the page caption, separate from photo dragging.

Canonical JSON types are in src/core/types.ts; native serde types MUST use camelCase and exactly these fields. Rust collage-core is the sole production layout/cover and photo-color implementation, built native and WASM. Resolved coordinates are document pixels; saved focus is oriented source-normalized; zoom is 1–100 relative to cover (direct interactive zoom is capped at 8x). Frame rectangles resolve from the template or normalized page overrides. Rotation is a finite number in [-180, 180] degrees, positive clockwise in document coordinates. EXIF orientation is applied separately before user rotation. flipX and flipY must remain false; unsupported flips are rejected. Template snapshots are embedded in Project.templates.

Project.canvasSizing is optional in JSON and accepts `first-photo` or `fixed`. New projects default to `first-photo`; older projects without the field normalize to `fixed` and preserve their saved document size. A new first-photo project previews 4000x6000 until its first valid import. With no previously registered project assets, assignAssets sizes the canvas from assets[0].width/height, the EXIF-effective original dimensions: k=floor(max(width,height)/3), clamped to 50–4082, and document size becomes 2k x 3k. Thus both 4672x7008 portrait and 7008x4672 landscape photos produce a 4672x7008 portrait canvas. The minimum is 100x150 and the maximum is 8164x12246, below 100 MP and the UI's 16000-pixel side limit. Existing pages' horizontal margins/column gaps and vertical margins/row gaps scale with the document dimensions. First sizing and photo assignment are one undo entry. Subsequent imports, crop/focus, zoom, rotation and template changes never recalculate output dimensions. Explicit manual document edits set the policy to `fixed`; the fixed 2:3 preset is 4000x6000, with 3:4, 4:5, 9:16, 1:1 and custom options retained.

A single click selects a photo for direct composition editing, with a green outline and four corner handles. Dragging inside the selected photo moves it; dragging those corners is the primary proportional zoom control, with wheel and pinch also available. A double click inside an empty or occupied frame enters independent frame-layout editing, showing a yellow outline and eight corner/edge handles. A left click outside that frame confirms the frame adjustment and exits that mode. Single-click photo adjustment, double-click frame adjustment and outside-click completion remain the primary interaction; F / **编辑照片框** and V / photo mode are auxiliary controls. Escape exits ordinary photo/frame editing, cancelling any currently active pointer transaction. The modes never show both handle sets or apply a pointer gesture to both geometry and photo transforms. Color controls live in the adjustment tool panel; the independent rotation panel has been removed. The right photo inspector collapses page/spacing settings and does not duplicate zoom or rotation controls. Reset restores focus (0.5,0.5), zoom 1, rotation 0 and all color adjustments to neutral without replacing the asset. Command Z / Shift Command Z undo and redo project changes; one continuous ordinary gesture commits one transaction. History retains up to 80 entries with a 64 MiB serialized-snapshot budget, so unusually large documents may retain fewer entries. Reset is itself reversible.

Control T and Command T both start the same photo free-transform session for a selected placed photo; the context menu offers the same action. The session exits yellow-frame/background modes, selects the photo for composition editing and draws its actual rotated full-image bounds from the shared cover result, independent of the crop frame. Four corner handles proportionally zoom the image. A transparent outer band approximately 40 screen pixels wide provides direct, live rotation along the corners and edges: moving the pointer into this area automatically shows a curved double-headed rotation cursor, and dragging rotates around the image's rendered center. There are no persistent corner rotation icons. The center remains an invisible calculation point, with no center marker, draggable origin or internal circular grip. Rotation tracks successive angular deltas across the ±180° boundary and Shift snaps to 15° increments. A compact in-canvas confirmation bar exposes precise zoom percentage and angle entry, confirm and cancel. Enter confirms, Escape restores the complete transform from session entry. All pan/zoom/rotation gestures, wheel/pinch updates and numerical edits within that session share one transaction and become at most one undo entry; cancelling or confirming an unchanged session preserves redo. Zoom is relative to the shared cover scale and clamps to 1..100: the minimum fills the crop frame, aspect ratio is preserved and rotation remains covered. This does not add image stretching, perspective transformation or flipping.

photoRotationHitArea and photoRotationAt resolve the transparent rotation hit band in screen coordinates against the entire visible workspace, rather than constraining it to one page's cell or small corner hotspots. The band follows the outside of the actual full-image bounds, using a width of approximately 40 screen pixels regardless of document or viewport scale. Corner resize handles take priority within their 14-screen-pixel hit radius; the image interior continues to pan the photo. Rotation hits exclude page-title areas and remain within the workspace safe region. When actual image bounds extend offscreen, a fallback outside the visible crop preserves an accessible rotation area where space permits. If no safe outer area exists, no overlapping target is added; precise angle entry in the confirmation bar remains available. The rotation cursor persists during the drag, including when the pointer leaves the band, and clears when the gesture finishes or cancels.

EditorState.photoTransform is an ephemeral FrameRef, with beginPhotoTransform, commitPhotoTransform and cancelPhotoTransform actions. Re-entering or reselecting the same photo preserves its owned transaction. Selecting another frame/page, changing workspace or frame/background mode, an unrelated document edit, saving/exporting, or undo/redo commits a pending session first. Loading or creating a document clears all session references. A failed document replacement leaves the existing session intact; a rejected transform commit rolls back and clears it without discarding redo. Runtime external-image refresh updates the current document and transaction's original snapshot together, so cancellation restores composition while retaining refreshed photo metadata. Pointer completion does not commit an active free-transform transaction; pointer cancellation cancels the session. Thumbnail drag eligibility rejects any active session, including a transfer captured before the session began. The adjustment panel is hidden until free transform is confirmed or cancelled.

The right inspector always exposes a compact **模板背景** section, including while a foreground photo is selected. Page.background is the opaque six-digit `#RRGGBB` sRGB solid color. Clicking its color button opens an RGB/HEX dialog with live preview inside one owned project transaction: cancel restores the previous page, confirm creates at most one undo entry. RGB channels are integers 0–255; short or six-digit HEX input normalizes to lowercase six-digit color. Saved color swatches are a separate application localStorage palette, up to 24 canonical unique colors. Storage writes must succeed before the visible palette updates; blocked storage reports failure and retains the prior palette. Swatch persistence never edits the project or its history. The separate system selection action opens HTML input[type=color]. The desktop eyedropper invokes `sample_screen_color`, opening AppKit NSColorSampler on the main thread; clicking returns the sampled color converted to encoded sRGB8 and normalized HEX, and Escape returns null without changing the page. Extended-gamut/HDR channel values clamp to the opaque sRGB8 document model; nonfinite values are rejected. The app does not capture or persist an image for sampling. Browser preview uses EyeDropper when available, otherwise its eyedropper action opens the system color UI. Native sampler integration and conversion tests do not by themselves prove that actual screen selection and cancellation have been exercised.

Page.backgroundImage is optional `{imageAssetId:string, opacity:number, transform:ImageTransform}`. It references an existing authorized project asset, has finite opacity in [0,1] and finite cover zoom in [1,8], and shares EXIF-effective cover geometry and transform validation with foreground photos. Missing legacy backgroundImage means solid color only. Transparent source PNG alpha multiplies the layer opacity. Native serde uses optional background_image with default/skip-if-none, and the serialized field remains backgroundImage. Page copying clones the background composition; subsequent edits are independent. Applying a template preserves page background. Saved reusable layout templates remain geometry-only, without background/photo metadata.

Background editing is an exclusive ephemeral mode, separate from selected foreground photos and frame-layout editing. Choosing an image or dragging a registered asset onto the right background drop region assigns a page background; native file drops into that region import an original and assign it. While background editing, canvas drags pan its focus and corner handles, wheel and pinch adjust its cover zoom. There is no inspector zoom slider. Opacity uses the right-side slider and a continuous gesture creates one undo step. Escape completes background editing. Restore resets the background transform to defaults while preserving opacity and solid color; replacement, including the same asset again, resets transform and opacity to 1. Remove deletes only page.backgroundImage and leaves the solid color and foreground placements intact. Frame/photo selection, page changes and project load clear background editing. That mode is never serialized.

assignBackgroundAsset follows the same first-photo sizing rule as foreground import when a new reference-first-photo project has no registered assets. Subsequent background changes, crops and zoom never resize the document. Background and foreground placements sharing an original keep independent transforms. Asset synchronization, project registration, original-file authorization, thumbnail fingerprints, history refresh and export snapshots include background asset references; refreshed original metadata preserves background composition and does not add undo entries.

The separate **编辑照片框** mode edits layout rather than photo composition. Double-clicking a frame's interior, including an empty frame, enters the mode and selects that frame. Dragging inside its yellow outline moves the rectangle; eight corner/edge handles resize width and height independently within the page. Geometry remains constrained to the page: a frame spanning the entire page width/height has no translation room on that axis and must first be narrowed/shortened with an edge handle. The editor explains this constraint rather than treating a clamped drag as a broken interaction. Clicking outside the frame with the left button commits the adjustment and leaves frame mode; F and the toolbar enter it explicitly, while V returns to photo mode and Escape exits, cancelling any active pointer gesture. Ordinary photo editing continues to pan and proportionally zoom the source inside the rectangle; the separate free-transform session adds actual photo bounds and a transparent outer rotation band with a contextual curved-arrow cursor. Existing split divider handles remain available for structured layouts; frame overrides and free layouts expose no shared divider handles. Each continuous frame gesture is one undo transaction and preserves photo transforms; mode transitions are ephemeral and do not serialize or add undo history on their own.

Regression coverage must keep these interactions separate: frame move/resize changes geometry while retaining the photo's complete transform, photo pan/zoom changes that transform while retaining frame rectangles, double-click/outside-click and F/V route to the intended mode, and continuous gestures remain one undo entry. Export checks must remain independent through active photo gestures, page browsing, page creation, document edits, deletion, undo/redo and stable onlySelected viewports. Scope tests cover exact checked IDs, zero checks, current/all scopes, stale page filtering, frozen export targets and direct single-page export independent of checks. Template-saving tests cover nonactive target-page geometry and layer order, unchanged editor state and transactions, and stale page rejection without active-page fallback. Named templates, layer order, exact photo drop targets, cross-page swaps, original-image synchronization and original-resolution export retain their existing behavior.

Right-clicking either an empty or occupied frame offers **置于最上层** and **置于最下层**, independent of frame-editing mode. reorderFrameLayer(ref, 'front' | 'back') reorders Page.frames bottom-to-top, committing a preceding gesture separately and recording one undo entry for an actual order change. Already-front/already-back, single-frame and stale-reference actions do not add history. Frame IDs, slot IDs, geometry, asset references and photo transforms remain unchanged. Layers require no new JSON field: existing page.frames order is the persisted order, including after save/load, copying a page and undo/redo. The shared Rust layout sorts resolved frames by that placement order while retaining slot-keyed template geometry, so WASM preview, thumbnail overlays and native export agree. Empty frames remain editable drop targets and do not paint over earlier photos.

The adjustment tool panel can float, move by its title bar and dock when dropped at the window's right side. Its settings expose opacity plus explicit dock and float actions. Position, docking and opacity persist at application level, outside Project JSON and composition undo history. There is no independent rotation panel or panel-grouping control in the current UI; rotation belongs to the canvas free-transform session. Existing saved panel preferences remain readable for compatibility, and the retained adjustment panel restores its stored placement and opacity.

ImageTransform.adjustments is a nondestructive per-placement PhotoAdjustments object. UI order and canonical keys are exposure, temperature, tint, contrast, highlights, brightness, shadows, vibrance, saturation, blacks. Exposure is finite [-3,3] EV; all other controls are finite [-100,100]. Neutral is zero for every field. Missing legacy adjustment objects or fields normalize to neutral; unknown keys, malformed objects, nonfinite and out-of-range explicit values are rejected. Store updateTransform accepts partial nested adjustments and merges finite clamped values without changing immutable source metadata or other placements sharing that source. Same-page and cross-page occupied swaps or moves into empty frames carry the full photo transform, including focus, zoom, rotation and all ten color values, with the placement; undo/redo restores that complete state.

Manual composition or color changes affect only the selected placement. Reset and replaceFrame restore the complete default transform: focus (0.5,0.5), zoom 1, rotation 0 and all ten color values 0. Replacement resets even when the incoming asset ID equals the current asset ID; removing the photo resets the emptied frame as well. These edits are undoable, but resetting an already-neutral placement need not add a history entry. Deleting the frame itself remains distinct: its occupied photo moves to unplaced with the transform preserved.

PhotoColorTransform::new(&PhotoAdjustments) and .apply([f32;3])->[f32;3] consume and return unpremultiplied linear-light sRGB in [0,1]. Exposure applies a 2^EV gain, distinct from brightness's perceptual gamma adjustment. Relative temperature/tint gains shift warm/cool and green/magenta; their luminance is normalized. A precomputed luminance tone LUT handles brightness, midpoint contrast, broad shadows/highlights and a separate deep-black mask. Saturation changes chroma uniformly, whereas vibrance preferentially changes muted colors. Output is clamped. Shared adjust_srgba8 and WASM adjust_rgba(pixels:Uint8Array,adjustmentsJson:string)->Uint8Array decode sRGB8, run the same linear pipeline and encode sRGB8; neutral preserves exact bytes and all adjustments preserve alpha. Native export applies the same transform to decoded original pixels before geometric filtering, unpremultiplying/re-premultiplying alpha as needed. Preview and thumbnail caches include both source fingerprint and adjustment values.

LayoutNode is tagged kind leaf/split/grid/free. split.parameter selects normalized weight arrays in page.templateState, fallback template.defaults. grid rowsParameter/columnsParameter select normalized track arrays. Structured layouts apply margin at root only; columnGap is gap between columns and rowGap between rows. Layout returns frames plus handles with constraints. All struct fields mirror types.ts. handle min/max represent allowed normalized cumulative boundary in available parent length excluding gaps, index between weights[index] and weights[index+1]. handle.rect is line hit geometry in document units; UI supplies CSS hit slop. Structured children have a minimum of 48 doc px (scaled down for tiny documents), constrained recursively. Shared grid handles span the parent.

Page.frameRects is an optional Record<slotId, Rect> containing normalized whole-page rectangles. When present, it must cover every template slot exactly, with no extra keys, and overrides split, grid or free geometry. LayoutNode `{kind:'free', frames:ResolvedFrame[]}` is allowed only at the template root; its 1–64 unique frame slots must exactly match slotOrder. Free and override rectangles require finite x/y >= 0, positive width/height, and right/bottom edges <= 1 with a 1e-9 floating-point tolerance. Overlap is allowed. Both multiply normalized coordinates by document width/height, ignore margin/gap when resolving geometry and return no divider handles. Legacy JSON without frameRects has no override; absent overrides are omitted on serialization. The same shared geometry resolves preview and original export.

Any page layout, including adjusted frame rectangles and their layer order, can be named and captured as a new free template in the left **我的模板** library. Every workspace page header and overview thumbnail card exposes an always-visible text action **存为模板**, including single-page views and dense multi-page views. PageTemplateAction supplies that page ID without activating it or changing export checks. App captures the project ID and explicit target page ID when opening SaveTemplateDialog; its preview, page number and initial name refer to that target rather than activePageId. Project switches or target-page deletion disable saving and explain the stale target. Submission synchronously rechecks both IDs and calls savePageTemplate(name, pageId); a missing explicit page rejects instead of falling back to the active page. The optional pageId preserves compatibility with existing active-page callers. Saving to the library leaves document photos, transforms, active/visible pages, selection, history and any transaction unchanged. On success App opens the left sidebar, even if previously hidden, and a reveal signal selects its template tab and **我的模板** library so the newly saved item is immediately visible. The application localStorage library persists layout geometry and layer order only, without photos or color adjustments; saved free root.frames and slotOrder both follow the current bottom-to-top page order. Applying a template embeds its snapshot in Project.templates. Normalized whole-page rectangles adapt to other document pixel dimensions. Applying even the same template clears page.frameRects and restores template geometry while retaining slot-mapped photo composition parameters. New pages and switching to a different template use its saved slotOrder as the initial bottom-to-top layer order. Free-frame add/remove keeps 1–64 frames; removing an occupied frame moves its photo to unplaced with its transform preserved. The library itself is application state; applying a layout or editing project frames is undoable project state.

The library stores an atomic `{templates, removedTemplates}` snapshot under its existing localStorage key; legacy array snapshots remain readable and migrate on the next successful write. Each personal template card exposes a separate always-visible delete button, outside the apply button. Deletion confirms the named layout, records a complete geometry snapshot in removedTemplates and hides that ID from both the library and Project.templates-derived personal entries. Embedded project snapshots remain unchanged, allowing existing pages, new pages based on them, preview, native export and composition undo/redo to continue. Reopening projects does not resurrect a removed entry. The collapsed **已删除** section restores individual snapshots to the reusable library; there is no irreversible purge action. Save of a removed ID clears its removal record. Persistence failures report the operation and leave both collections intact. Built-in IDs and non-custom categories cannot be saved, deleted or restored as personal templates. Library deletion/restoration leaves document dirty state, active pages, selection, assets, photo transforms and project history unchanged.

The 25 built-ins include the original 13 structured layouts and 12 photographic design layouts using existing normalized free geometry, four each for 2/3/4 images. **设计** filters the added layouts while the image-count categories include them too. Negative space, asymmetric alignment and dominant-photo/detail relationships live in whole-page frame rectangles; page margins and gaps remain zero. The example **上满下留白** fills the upper 60% with one photograph and centers a smaller lower frame, with whitespace on every side of that lower photograph. All designed frames support the same double-click editing and capture-as-personal-template flow. Vector template previews use the actual 2:3 canvas geometry without extra artificial spacing for free templates. References: [Canva design grids](https://www.canva.com/features/design-grid/), [Canva photo grids](https://www.canva.com/create/photo-grids/), [Canva collage ideas](https://www.canva.com/ideas/photo-collage-ideas/) and [Adobe Express photo collages](https://www.adobe.com/express/create/photo-collage) informed the use of whitespace, visual hierarchy and editorial arrangements. Coordinates are original; no external photos or assets are bundled.

Cover returns document-space centerX/centerY and rotation, plus full-image unrotated scaled width/height; x/y are center minus half those dimensions. crop is the axis-aligned envelope of the inverse-rotated frame in EXIF-oriented source pixels. Rotated cover clamps effective focus so all inverse-mapped frame corners stay inside the original photo. Direct photo drags inverse-rotate document displacement and derive focus from the actual rendered center, avoiding jumps from previously clamped focus intent.

Native IPC (camelCase args): import_assets(paths:string[]) => {assets:ImageAsset[],errors:string[]}; get_proxy(assetId:string,maxSize:number,asset?:ImageAsset) => absolute cache path string; register_project(project:Project) => {missing:string[]}; save_project(project:Project,path:string) => void; load_project(path:string) => Project; relink_asset(assetId:string,path:string) => ImageAsset; open_in_photoshop(assetId:string,asset?:ImageAsset) => void; refresh_assets(assets:ImageAsset[]) => {assets:ImageAsset[],errors:string[]}; start_export(project:Project,options:ExportOptions) => jobId string; cancel_export(jobId:string) => void; get_export_progress(jobId:string) => ExportProgress|null. Native emits export-progress (ExportProgress). Frontend uses convertFileSrc for app cache paths only. Native original access checks registered asset metadata versions and fingerprints; get_proxy, open_in_photoshop and refresh_assets use the current authorized asset snapshot so relink undo follows the document's current path. Unknown IDs or unapproved metadata/path substitutions are rejected. Native dialog plugin handles open/save/folder picker. Runtime proxy URLs never stored in project. start_export snapshots original fingerprints; runs one job at a time with checked decode budgets, atomic per-page writes, cancellation and progress.

Native screen sampling IPC is `sample_screen_color()` => `string|null`: an opaque lowercase `#RRGGBB` on selection, null on user cancellation, or a reported error. The AppKit callback retains its sampler for the session and returns only plain color data across the async boundary.

Right-clicking a placed photo offers **在 Photoshop 中编辑**, which opens its authorized snapshot's original path in installed Photoshop. Saving back to that same path is detected by native refresh_assets. Native watch baselines are keyed by asset ID plus original path and retain the metadata corresponding to each stable file stat; unchanged files need only a metadata check. Changed stable files are hashed and inspected for EXIF/ICC and effective dimensions, with brief save transients retried before reporting errors. Responses contain metadata differing from the caller's snapshot, including already-known same-path updates when the caller is stale. Refreshing a path restored by undo does not replace an unrelated explicitly relinked default path.

The frontend polls every 2 seconds while visible and also on window focus/visibility return. Polls and export-before-snapshot synchronization share one serialized queue and capture current asset snapshots when their turn executes. A response is applied only if the current asset still matches its request snapshot's ID, original path and fingerprint, preventing a late poll from overwriting manual relink or undo. Export waits for that synchronization before taking its immutable project snapshot. Stable refreshed metadata retains the asset ID and original path, updates fingerprint/effective dimensions, and invalidates proxy/color/thumbnail caches. Store refreshAssets preserves all frames/transforms, document dimensions and canvasSizing, updates same-ID/same-path asset versions throughout undo/redo and active transactions, and introduces no undo entry. Revision identities advance so refreshed metadata remains dirty until saved; an old in-flight save cannot falsely mark the refreshed state clean. Older relink-history paths retain their own metadata. External pixel edits are not undone by application composition undo; saving to a different path requires replacement or relinking.

Rust render renders from originals only, EXIF normalized once, sRGB color handling explicit, high-quality fractional crop/resize and rotated sampling using the shared cover geometry. Layer order is solid page color, optional background original, then foreground frames in the shared layout's bottom-to-top page.frames order. Premultiplied RGB and alpha both receive background opacity, with linear-light alpha compositing over the current canvas; transparent foreground pixels reveal the background or previous overlapping frame. Empty foreground frames have no opaque preview fill and paint nothing in original export; editor outlines and drop guides are excluded from export. The browser's dedicated background preview blends source PNG alpha and layer opacity over the solid color in linear-light sRGB, matching native blend behavior; its LRU budget is 32 MiB and thumbnails use that same background image. Proxy source changes invalidate the corresponding preview through new source identity and thumbnail asset fingerprints. JPG is the default format at quality 100 with 4:4:4 encoding; PNG is selectable and lossless. Both formats encode an opaque page. Native file save atomic. No original overwrite. No filesystem or bitmap data in geometry WASM.

Long-image creation takes 2–64 authorized ImageAssets in explicit order and produces a normal one-page fixed-size Project with a free root template, zero margins/gaps and default photo transforms. The initial frame aspect equals its source's EXIF-oriented aspect, preserving complete photographs. Vertical cross size defaults to the first photo's width; horizontal cross size to its height. A user cross size and document-pixel gap are optional. The continuous layout is uniformly reduced to satisfy both 32768px per side and 268435456 total pixels after integer-ceiling canvas dimensions. Normalized free frames preserve subpixel source aspect, with at most the canvas rounding remainder left blank. This workflow never inherits ordinary first-photo 2:3 sizing. App protects unsaved current work before opening creation, then registers the generated Project and marks it unsaved. Existing photo controls, double-click yellow frame controls, layer ordering, history, project serialization and native export apply without a separate editing model. Window-fit and view zoom support small scales required by long documents.

Batch watermarking is independent application state, without access to composition state or its undo history. A transparent, nonempty PNG, a reference photograph, a scanned input directory and a separate output directory are required. Placement stores `{x,y,widthRatio,opacity}`: x/y are in [0,1] of remaining movable space, requested watermark width is photo short edge times widthRatio in [0.01,2], opacity is [0,1]. The complete PNG is proportionally contained inside each photograph if necessary. Frontend preview, direct drag, four aspect-locked corner handles, keyboard nudges and nine anchors use the same continuous geometry as native output. Named localStorage profiles store PNG path and placement; same-name save updates its ID. Last settings store reference/PNG paths, folders and format. Reloaded paths are explicitly reimported and authorized; unavailable originals report errors. Persistence failures retain the previous stored state.

Watermark IPC: `import_watermark(path)` => ImageAsset; `scan_watermark_directory(directory)` => `{directory,assets,errors,skipped}`; `start_watermark(options)` => jobId; `cancel_watermark(jobId)`; `get_watermark_progress(jobId)` => ExportProgress|null. Options include scanned asset snapshots, authorized watermark snapshot, inputDirectory, output directory, placement, jpg/png format and quality. Scans cover only immediate regular JPG/JPEG/PNG files, ignore symlinks/subdirectories, use natural filename order and limit batches to 5000 photos. Start verifies the current directory scan, all asset authorizations and canonical distinct folders, then excludes the watermark itself. The native queue shares the image memory gate with collage export, serializes original decode/render, retains EXIF-effective photo dimensions and outputs opaque sRGB JPG100/PNG with linear-light PNG alpha and layer-opacity composition. Temporary output commits atomically to a new `stem-水印` filename with collision suffixes, preserving originals and existing output. Per-photo failures continue the batch. Cancellation removes uncommitted current output and retains completed outputs.

`watermark-progress` uses ExportProgress; UI filters by job ID, rejects regressive/late progress and polls to recover missed events. Starting/running/cancelling locks settings and prevents modal dismissal. Requested dismissal offers cancel-and-wait until native termination; busy status protects window close, and native ExitRequested protects application quit while jobs are active with `watermark-close-blocked`. Terminal state releases the busy guard. Starting/closing tasks never replace the current collage project, selection or history.
