交付版本：**2.0.0-rc.1 候选版**。汇总日期：2026-10-27（亚洲/上海）。

本次已完成源代码修改、自动测试、原生构建及本机真实界面验收。项目、草稿、自动保存、素材重连及完整归档已可使用。**尚未完成 Apple 信任分发和另一台 Mac 的真机验收，因此没有创建稳定版 `v2.0.0` 标签。** 最终兼容性报告保留 Gatekeeper 的实际失败结果。

应用沿用规范的用户应用数据目录，发布目录及 APP Bundle 不存放用户作品：

| 可清理代理缓存 | `~/Library/Caches/com.framestudio.collage/proxies/` |
| 诊断日志 | 应用数据目录的 `logs/startup.jsonl` |

| 完整 ZIP、另存 `.collage` | 每次由用户通过保存窗口选择位置 |

正式项目和临时草稿不混列。项目库使用独立 `formatVersion = 2` 外层容器，画面数据继续使用 `Project.schemaVersion = 1`；普通项目保存原图引用，不默认复制全部高清图片。

自动保存覆盖所有页面、画布、模板、照片框几何、层序、背景、素材、裁切焦点、缩放、旋转和调色，并保存当前页、同屏页、导出勾选、视图缩放等有效视图状态。内存撤销栈、鼠标事务及未确认的自由变换会话本身不跨启动恢复；最后成功写入的画面参数可恢复。异常退出时，防抖窗口及尚未完成写入的修改可能丢失，不能把约 1 秒防抖当作固定丢失上限或断电零丢失保证。

升级前已保留原 WebView 数据和偏好到 `artifacts/v2/pre-upgrade-data-20261026/`；实际当时工作区为一页空白、一个自定义模板。通过旧版原生界面另存的备份为 `artifacts/ui/用户工作区备份-20261026-V2升级前.collage`，未覆盖原用户文件。旧恢复记录迁移前保留原键和独立备份，摘要标记防止重复迁移。

打开旧 `.collage` 时建立独立草稿，不自动写回原文件；需要输出 JSON 项目副本时明确选择「另存项目文件副本」。普通 `.collage` 不含原图，不能代替完整归档。

## 3. 智能重连机制

素材保留 ID、原路径、文件名、有效宽高、内容 BLAKE3 指纹，增加初始路径、来源根目录、相对路径、大小及最多 16 个历史根目录。图层保持通过素材 ID 引用原图，失联不会删除照片框或排版。

检查顺序为原路径、关联目录相对位置、历史目录及用户指定目录，再在限定范围内寻找同名候选。自动连接必须核对指纹、有效尺寸和已有文件大小，不能仅凭文件名或肉眼相似静默替换；多个可信候选仍要求人工选择。明确逐图定位可由用户确认使用的新文件。

后台每约 2.5 秒和窗口重新激活时检查，`/Volumes` 挂载目录变化会使扫描缓存失效。原路径恢复可自动重读；改卷名或改目录后可选择一次新的素材文件夹批量恢复。重连更新高清预览缓存身份，保留构图、调色、层序以及撤销历史中的素材引用。

扫描仅在已关联或用户选择的目录内执行，不跟随符号链接目录，最多 64 个根目录、6 层、10,000 个目录条目或约 3 秒目录枚举预算。候选图片的完整指纹和尺寸校验不计入该 3 秒，慢盘或大项目总耗时可能更长。达到限制会提示选择更精确的子目录。当前分发不启用 App Sandbox，遵循 macOS 正常文件权限；目录记录不能绕过 TCC，权限不足仍需重新选择或由用户处理系统授权。

离线时尽可能使用已有代理缓存，缓存不存在时只能显示占位。成品导出和完整归档始终要求真实原图，不把低清缓存冒充高清原件。

## 4. 归档说明与迁移

操作：正式项目顶部「项目操作 → 打包归档」，选择新 ZIP 文件位置。导入则选择「项目操作 → 导入归档」或项目抽屉的同名按钮。应用后台显示校验、复制和导入进度，可取消；安装项目的最后提交不可被事后的取消逆转。

归档包含 `project.json`、`manifest.json` 和 `assets/`。全部已登记原图（含背景及待排素材）只读复制到包内唯一名称，不移动或改写原图，原项目引用不变。归档副本清除原机器的绝对来源目录，使用相对路径；清单记录版本、完整标志、素材 ID、大小、尺寸及 BLAKE3，ZIP 另有 CRC 校验。

导入创建新存储 UUID 和新文档身份，独立保存包内原图，不依赖最初路径或覆盖同名作品。只在安全临时目录完成结构、版本、CRC、指纹和素材对应校验后提交项目。拒绝路径穿越、绝对路径、非法链接、设备文件、重名冲突、重叠/越界条目、截断、异常展开量和不完整清单。

本版输出标准 Store ZIP，输入支持 Store/Deflate；不支持 ZIP64、加密、多卷和部分归档。单文件上限 1 GiB，总展开上限 2 GiB，最多 20,010 条目；项目容器上限 34 MiB，附加视图状态上限 128 KiB。超限明确失败而非破坏已有作品。没有额外生成可选的整页归档预览，完整原图与编辑数据均包含。

迁移机制已用原路径全部失效时的真实导入、编辑、保存、重开及导出验证，也有独立项目库自动测试。**另一台物理 Mac 的实际迁移仍未执行**；导入机制通过不等于所有接收系统都能启动当前未公证 APP。

## 5. 历史兼容性经验复用

已只读找到相邻电商跑图系统的历史代码、提交及诊断记录，没有修改该软件。关键提交 `106d60a34a31bda8d21b15eed5522aa4cf205ca2` 及原报告确认：M2 Max / Ventura 13.4 当时阻断为飞书来源硬隔离位 `0x0004`，系统报 `File created by an AppSandbox, exec/open not allowed`，发生在业务入口前。权限、arm64 和严格签名完整性正常，不能归因为 M2 芯片或缺少运行库。

历史处理以独立测试副本、正常 LaunchServices 启动、只读分发诊断及绑定产物摘要为核心，没有把关闭系统保护作为修复。其他历史问题还说明不能只信软件最低版本声明，需要检查所有原生加载命令和依赖。本工程是 Tauri/Rust，不照搬 Python/Qt 依赖方案。

本次迁移了真实 Mach-O 架构/最低系统/依赖检查、签名与 Gatekeeper 分别记录、直接隔离属性诊断、绑定 APP/DMG 摘要、无开发环境依赖的接收端诊断和隐私受控日志。发现旧拼图实际最低 14.0 后，将原生部署目标设为 13.0、前端构建目标设为 Safari 16，并在独立构建目录真正重新编译；最终二进制确认为 13.0.0。

历史已认证 SSH 控制 socket 已不存在，无法复用旧会话。没有读取凭据或重新建立权限，也没有部署新版到远端；这里只能认定旧会话不可复用，不能声称测试机离线。详细引用见 [兼容性复盘](v2-history-compatibility.md)。

## 10. 遗留问题与后续验收

1. **发布信任未完成。** 当前 ad-hoc 包完整性正常，Gatekeeper 实际拒绝。没有有效 Developer ID 身份和公证授权，无法在本轮补齐；需开发者签名、公证后针对新摘要重新构建和测量，当前包保持 RC。
2. **跨机真机矩阵未完成。** 旧远程会话不可复用，M1/M2/M3/M4、Ventura 真机、实体磁盘插拔及跨电脑传输仍待实际测试。已经准备只读诊断和精确产物证据绑定，没有把静态通过写成真机通过。
3. **明确的体积与运行边界。** ZIP/项目体积有上述上限；大图或慢盘验证耗时受真实设备影响。尚无真实大型摄影项目的性能基准。非 App Sandbox 分发，无云同步或 Mac App Store 安全书签适配。
4. **恢复与备份边界。** 自动保存恢复最后成功快照，不恢复内存撤销栈；普通项目和复制作品仍依赖外部原图。应定期生成完整 ZIP 并保存到独立介质。已有原图丢失且无缓存/归档时不能还原高清照片。
5. **既有格式边界。** 当前仍以 JPG/PNG 输入为主，HEIC、RAW、Intel、Windows 未在本轮加入；不把这些旧边界视为已完成能力。
